LESSON 01 / PRODUCT DESIGN

何を商品にするか決める

知識より先に、誰の何を解決するのか。

このテーマの到達点

経験を棚卸しし、購入者の困りごとと結びつける。

この記事の目次
  1. 1. このテーマで学ぶこと
  2. 2. 技術の中身
  3. 3. よくある間違い・つまずき
  4. 4. 実践例：試験対策教材の課題を切り取る
  5. 5. まとめと次への繋ぎ

1. このテーマで学ぶこと

要点は4つ。

  1. 商品や記事は「知識」からではなく「困りごと」から決める。この教材では、「誰が」「何に困っていて」「どうなれば解決か」を先に固定することを勧める
  2. 困りごとは「検索される言葉」の粒度まで具体化する。「コーヒーが上手く淹れられない」ではなく「ドリップバッグを開けたら粉がこぼれた」のレベルまで落とす
  3. 困りごとの素材は3か所にある。自分の実務の現場、購入者・読者の声、検索の現場（サジェストや関連キーワード）。この3か所を行き来して見つける
  4. 対象を絞ることは弱さではない。「誰にでも役立つ」は検索にも人の記憶にも残らない。対象を絞るほど、言葉が具体化し、届く相手には深く刺さる

このテーマのゴールは、「自分が扱う困りごとを、相手が検索窓に打ち込む言葉で言い表せる」状態になることである。

2. 技術の中身

2-1. 困りごとの3要素： 誰が・何に・どうなれば

課題の切り取りの基本形は、次の3つを1文で言えるようにすること。

  • 誰が： 状況まで含めた人物像（例： 「コーヒーインストラクター1級の受験勉強を始めたばかりの人」「初めてドリップバッグを買った人」）
  • 何に困っているか： 本人が口にする言葉での困りごと（例： 「過去問がどこで手に入るか分からない」「レシピ通りに淹れたのに味が安定しない」）
  • どうなれば解決か： 解決後の具体的な状態（例： 「過去問の入手先と使い方が分かり、勉強の進め方に迷わなくなる」）

この3つが揃わないまま記事や商品を作ると、内容は「知識のまとめ」になり、読む側は「自分向けかどうか」が判断できない。判断材料がないと、買うかどうかも読み進めるかも決めにくい。

2-2. 粒度を下げる： 抽象語から検索語へ

困りごとは、見つけた時点では大抵抽象的である。「試験に受かりたい」「コーヒーが上手くなりたい」。そこから粒度を下げる作業が切り取りの中心になる。

粒度を下げる質問は3つ。

  • いつの困りごとか（勉強を始めた日か、試験の直前か。淹れる前か、淹れている最中か、飲んだ後か）
  • 何と比べて困っているか（店で飲んだ味と違う、前回と味が違う、合格ラインが見えない）
  • 本人は今、どう検索するか（そのまま検索窓に入れる言葉を想像する。「コーヒーインストラクター 1級 過去問」「ドリップバッグ 淹れ方」の形）

目安として、タイトルにそのまま使える言葉になったら粒度が足りている。逆に、タイトルに置くと説明が必要になる言葉は、まだ抽象度が高い。

2-3. 困りごとを見つける3つの現場

① 自分の実務 最も強い素材は、自分の仕事や経験の中にある「他人が困っていて、自分には当たり前」な部分である。当たり前すぎて本人は価値に気づかないが、外の人にとっては知りたくても聞く相手がいない情報であることが多い。見つけ方のコツは、「最近、誰かに説明したこと」「初心者がつまずくのを見た場面」「自分が昔つまずいたこと」を棚卸しすること。

② 購入者・読者の声 既に売れた商品の購入者の感想、記事へのコメント、質問のメールなどには、困りごとが本人の言葉で書かれている。自分の言葉で言い換えず、書かれたままの表現を収集するのが要点で、その表現がそのまま次の記事のタイトルや販売ページの言葉になる。声がまだ少ない場合は、似たジャンルの商品のレビュー欄や質問欄も観察対象になる（内容の転用ではなく、困りごとの傾向を読むため）。

③ 検索の現場 検索エンジンのサジェスト（入力候補）や関連キーワードは、検索される可能性のある言い回しを探すための手掛かりである。テーマの種になる言葉を入れて、出てくる候補を記録する。候補に出たことだけで検索量や購入需要は分からないため、需要の検証は別に行う。自分の思いつきだけでテーマを決めるより、まず検索で使われる言い回しを確認し、実際の質問や反応と照合する。

2-4. 絞り込みの判断基準

候補が複数出たら、次の3点で優先順位を付ける。

  1. 自分が一次情報を持っているか（実務・実体験で語れるか。これが差別化の根拠になる）
  2. 解決後の状態を具体的に描けるか（記事なら「読めばできるようになること」、商品なら「使い終わった後に残るもの」が言えるか）
  3. 既存の資産と繋がるか（過去記事、販売中の商品、企画中のツールへの導線が作れるか）

なお、このジャンルには「不安を強く煽ってから解決策を売る」「困りごとを実際より大きく見せる」といった切り取り方も存在する。困りごとの誇張は短期的に反応が取れても、実務の一次情報と正直さが信頼の源泉である売り方とは両立しないため、この教材では採らない。困りごとは「実際にあるものを、正確に、相手の言葉で」切り取ることに徹する。

3. よくある間違い・つまずき

  • 自分の書きたいことから始める：「これは知ってほしい」という書き手の都合でテーマを決めると、読者の困りごととずれる可能性がある。順序は常に「相手の困りごと→自分の知識」の向き
  • 対象を広げすぎる：「コーヒー好き全員向け」では誰に向けた記事かが曖昧になる。広げる判断は、まず絞って届いた後の話
  • 困りごとを自分の言葉で言い換えてしまう： 購入者の声や検索の言葉を「綺麗な表現」に直すと、検索との一致も、本人の「自分のことだ」という感覚も消える。生の言葉を残す
  • 困りごとを1記事に詰め込みすぎる： 1記事1つの困りごとが原則。複数の困りごとを束ねるのは「商品化」（テーマ2）の仕事であり、集客の記事では分ける
  • 売れた実績のあるテーマから目を逸らす： 既に読まれた・購入されたものがある場合、それは読者が何を必要としたか考えるための手掛かりになる。新規テーマより先に、その周辺の困りごとを掘る方が確度が高い

4. 実践例：試験対策教材の課題を切り取る

商品企画の例として、コーヒーインストラクター1級の受験対策を実践例としていた。この例で重要なのは「コーヒーの知識を売る」と決めることではない。受験する人が、具体的にどの場面で立ち止まるのかを分けることだ。

  • 誰が： 仕事をしながら1級の勉強を始める受験者。
  • 何に困る： 学ぶ範囲が広く、分野ごとに何から手を付ければよいか決めにくい。
  • どうなれば解決： 学ぶ順番が分かり、苦手分野を確認しながら進められる。

「コーヒーの試験対策」は大きすぎる。そこから「1級の学習順序をどう決めるか」「記述問題はどのように練習するか」のような個別の問いへ分ける。

この企画では、検索記事候補の選定と、想定問題をまとめた商品の対象読者の言語化を並行して進める計画だった。これは公開記事と有料教材を同じ課題から設計する例になる。ただし、検索候補に出るだけでは購入需要を確認できない。実際に寄せられた質問と、これから検証したい仮説は別々に記録する。

作業シート：困りごとを一文にする

  1. 自分が最近説明したこと、以前つまずいたことを3件書き出す。
  2. それぞれを「誰が／いつ／何ができない／どうなれば解決」に分ける。
  3. 読者自身が検索しそうな言葉へ置き換え、確認できていない箇所に「仮説」と書く。
  4. 最も実体験を使って答えられる課題を一つ選ぶ。

ここで決めた一文を、次のテーマの商品構成・目次へ渡す。

5. まとめと次への繋ぎ

  • 商品と記事は困りごとから決める。切り取りの形は「誰が・何に困り・どうなれば解決か」
  • 困りごとは検索される言葉の粒度まで下げる。素材は実務、購入者の声、検索の現場の3か所
  • 切り取った困りごとは、次テーマ「商品化・カリキュラム設計」で「順番とステップのある教材の形」に変えていく。困りごとが1つずつ固定されているからこそ、並べ替えと目次化ができる

制作時の確認ポイント

  • 想定読者を「全員」にしない
  • 経験のない実績を足さない
  • 買い手の言葉と自分の思い込みを分ける
