LESSON 02 / PRODUCT DESIGN

知識を商品に組み立てる

教材やnoteの価値は、情報量ではなく到達できる順番。

このテーマの到達点

ゴールから逆算して目次・章・演習を設計する。

この記事の目次
  1. 1. このテーマで学ぶこと
  2. 2. 技術の中身
  3. 3. よくある間違い・つまずき
  4. 4. 実践例：既存の記事を試験対策教材に組み直す
  5. 5. まとめと次への繋ぎ

1. このテーマで学ぶこと

要点は4つ。

  1. 「知識の量」と「教材としての価値」は別物。買い手にとって、情報だけでなく「迷わず最後までたどり着ける順番」も価値になる
  2. 商品化の中心作業は並べ替え。ゴール（できるようになる状態）から逆算して、学ぶ順番、1ステップの大きさ、確認の場（演習）を設計する
  3. 最初の商品化は新規執筆ではなく既存資産の再編集から始める。既にある記事・素材を目次順に並べ直す方が遥かに速く、売れた経験のある素材は、読者の関心を判断するための手掛かりになる
  4. 目次は設計図であると同時に販売材料。目次を見れば「自分向けか」「最後まで使えそうか」が判断できる状態にし、抜けている分野は目次の段階で見つける

このテーマのゴールは、「手持ちの知識・記事の集合を、ゴールから逆算した目次に並べ替え、不足を特定できる」状態になることである。

2. 技術の中身

2-1. ゴールから逆算する： カリキュラム設計の基本手順

教え方の設計（インストラクショナルデザイン）の基本は、書き手の「教えたい順」ではなく、学び手の「たどり着く順」に並べることである。手順は次の5段階。

  1. ゴールを1文で固定する： 「この教材を使い終わった人は、何ができるようになっているか」。テーマ1で固定した「困りごと→解決後の状態」がそのままゴールになる
  2. ゴールを中間の状態に分解する： ゴールに到達するまでに必要な下位の能力・知識を洗い出す（例： 「過去問を回せる」ためには「出題範囲の全体像」「分野ごとの基礎」「記述の型」など）
  3. 前提関係で並べる： 「これが分からないと次が分からない」という依存関係の順に並べる。これが目次の骨格になる
  4. 1ステップの大きさを揃える： 1つの記事・章で扱うのは「1つのできること」まで。大きすぎるステップは分割し、小さすぎるものは束ねる
  5. 確認の場を置く： 各ステップの終わりに「分かったか」を確かめる仕組み（問題、チェックリスト、やってみる課題）を置く。確認がない教材は「読んで終わる」ものになり、使い切った実感が生まれない

2-2. 既存資産の再編集による商品化

既に単品で公開・販売している記事群がある場合、商品化の作業は「新しく書く」ではなく次の3作業が中心になる。

  • 棚卸し： 全素材を一覧化し、各素材が「目次のどの位置に来るか」を仮置きする。タイトルだけでなく、中身の範囲（扱っている分野と深さ）を一行で記録する
  • 分類と当てはめ： 棚卸しした素材をゴール側の分野分けに当てはめる。この時点で「同じ分野に重なっているもの」「どの分野にも入らないもの」「分野はあるのに素材がないもの」が見える
  • 不足の特定： 素材がない分野が、そのまま「書き足しリスト」になる。反対に、分野に入らない素材は、無理に組み込まず単品のまま残す判断も正しい（既存の読者動線を壊さないため）

再編集の利点は速度だけではない。単品で購入された記事は読者の関心を知る手掛かりになる。ただし、複数記事を束ねた商品に同じ需要があるかは別に確かめる必要がある。

2-3. 目次の作り方

目次は次のルールで作ると、設計図と販売材料を兼ねる。

  • 見出しは「内容の名詞」ではなく「できること・分かること」で書く（例： 「生豆の成分」より「生豆の成分から焙煎の狙いを説明できる」）。買い手は目次で「使い終わった後の自分」を想像する
  • 順番は前提関係の順（2-1の手順3）。時系列や五十音順など、学習と無関係な並べ方はしない
  • 各項目に「何が入っているか」の一行メモを付ける。タイトルだけでは範囲が分からない項目は、買い手が範囲を判断しにくくなる
  • 総量が伝わる形にする（記事数、問題数、想定の学習期間の目安など、数えられる事実で示す）
  • 目次の段階で「向いていない人」も見えるようにする。対象外の人が買ってしまうことは、買い手にも売り手にも不幸であり、目次と対象の明示はその予防になる

2-4. 抜けの見つけ方

目次の抜け（カバーできていない範囲）は、次の3つの照合で見つける。

  1. 公式範囲との照合： 試験であれば出題範囲・公式テキストの章立てと目次を並べ、対応しない章を探す。最も客観的な方法
  2. 逆算の再点検： ゴールから分解した下位項目（2-1の手順2）のうち、目次に対応項目がないものを探す
  3. 買い手の声との照合： 購入者・読者の質問の中で、既存素材で答えられていないものを集める。「答える記事がない質問」が抜けの実例になる

抜けが見つかったら、重要度（試験なら出題頻度、実務なら困る頻度）と作成コストで優先順位を付け、全部を埋めようとしない。発売時点で埋まっていない範囲は、目次上も「収録範囲外」と正直に線を引く方が、誇張して全範囲を謳うより信頼を保てる。

なお、このジャンルには「中身より目次と見せ方を豪華にして実体を薄くする」作り方も存在する。目次は約束であり、実体が伴わない約束は返金・低評価・信頼の喪失として返ってくるため、この教材では採らない。目次は「実際に入っているもの」だけを、正確に書く。

3. よくある間違い・つまずき

  • 知識の網羅を目的にしてしまう： 自分が知っていることを全部入れると、ゴールへの道筋が見えない教材になる。入れるかどうかは「ゴールの逆算に入っているか」で決める
  • 書いた順・公開した順に並べてしまう： 執筆の履歴は学び手には無関係。前提関係の順に並べ替える作業を省略しない
  • 1ステップが大きすぎる： 「これで全部分かる」という大きな記事は、途中で脱落を生む。分割し、各ステップの終わりに到達点が見える形にする
  • 演習・確認を後回しにする： 読むだけの教材は「分かった気」で終わる。問題・チェックリストなどの確認の場は、目次設計の段階で一緒に置く
  • 抜けを隠して全範囲を謳う： 短期的には売れても、買い手の期待とのずれが評価を壊す。収録範囲は正直に線を引く（2-4参照）
  • 新規執筆から始めて力尽きる： 最初の商品化は再編集で形にし、書き足しは「不足リスト」に絞る。全部新規で作る設計は、完成前に止まる典型的なパターン

4. 実践例：既存の記事を試験対策教材に組み直す

商品企画の例には、コーヒーインストラクター1級に関する既存の試験対策記事18件を並べ替える計画が記されていた。これは数量を仮置きした設計例であり、実際の商品では現在の公開件数を確認する。

作業の中心は、単品記事をそのまま時系列で束ねることではない。学習目標を先に置いて、記事ごとの範囲を確かめる。

  1. 公式の学習範囲と照合する： 章立てを基準に、記事・問題・手元の資料を仮置きする。
  2. 重なりと不足を可視化する： この企画では、経営・指導法、抽出・官能評価、産地・銘柄の深い学習を不足候補として挙げていた。今も不足しているかは最新版の教材と照合して判断する。
  3. 見出しを行動で書く： 「焙煎」だけでなく「焙煎の基本を説明できる」「問題を解いて理解を確かめる」という見出しにする。
  4. 範囲外を明示する： 未収録の内容をあるように見せない。追加予定も確定したものだけを書く。

この例での成果物は、目次・各章の到達点・不足素材の一覧の3点である。後から単品を追加する場合でも、この設計図があると優先順位を判断しやすい。

作業シート：目次の下書き

  • 教材を終えた人ができるようになることを一文で書く。
  • 既存の文章・画像・問題を列挙し、対応する章へ置く。
  • 各章に確認問題、チェック項目、実践課題のいずれかを付ける。
  • 「不足」「重複」「対象外」を別欄で残す。

5. まとめと次への繋ぎ

  • 教材の価値は知識の量ではなく、ゴールまで迷わない順番の設計にある
  • 商品化は再編集から始める。棚卸し→分類・当てはめ→不足の特定、の3作業で目次と書き足しリストが決まる
  • 目次は約束である。入っているものだけを正確に書き、範囲外は線を引く
  • 次テーマ「オファーと価格」では、確定した目次（収録範囲）を材料に、「何を・いくつ束ねて・いくらで出すか」を決める。目次が先に固まっているからこそ、価格の根拠を買い手に説明できる形で設計できる

制作時の確認ポイント

  • 目次と実際の中身を一致させる
  • 先に100本の記事を作ろうとしない
  • 既存の素材を無理に全て入れない
